# Recallant v0.1.0-dev.3

`v0.1.0-dev.3` is a security and governance development prerelease. It keeps the existing
Codex-first governed-memory workflow and hardens the public HTTP, Workbench, filesystem, and CLI
boundaries used by remote clients and managed deployments.

## Install this release

```bash
curl -fsSL https://raw.githubusercontent.com/Mushkrot/Recallant/v0.1.0-dev.3/scripts/install-recallant-bootstrap.sh \
  | bash -s -- --ref v0.1.0-dev.3
```

Then verify the pinned identity:

```bash
recallant --version
# recallant 0.1.0-dev.3+<release-sha>
```

The universal beginner path remains `recallant onboard <project>`. Automatic native capture is
Codex-first; other clients can use configured MCP access.

## Security and governance fixes

- Forwarded client and Cloudflare identity headers are trusted only from the local reverse-proxy
  boundary. Direct-origin clients cannot spoof them to authenticate or evade rate limits.
- Copyable bootstrap and remote commands use a configured public URL or a trusted local proxy;
  untrusted request host headers cannot select their origin.
- Public JSON and form endpoints enforce bounded request sizes and return bounded error responses.
- Workbench model output cannot elevate a neutral request into a privileged global rule or project
  management action. Owner edits cannot change memory authority fields or store secret material.
- Project and vault file operations reject symlink escapes, and backup migration redacts multiline
  private-key blocks.
- Generated CLI commands shell-quote dynamic paths, identifiers, filenames, and URLs.
- Malformed URI and cookie inputs fail closed without terminating the HTTP service.

## Verification

The release gates cover format, lint, build, dependency audits, deterministic product tests,
request and filesystem security regressions, clean-host and pinned-ref installation, onboarding,
public readiness/security, remote integration rehearsals, and install rollback.

Database-backed gates require an explicit disposable PostgreSQL target via
`RECALLANT_SMOKE_DATABASE_URL`; they must never inherit service or production storage settings.
## Known limitations

- Native capture parity for Claude Code, Cursor, and Windsurf is not promised.
- General document crawling and PDF/DOCX ingestion are not included.
- npm package publication and stable `1.0` compatibility guarantees are out of scope.
- Operators remain responsible for access policy, backups, model availability, and capacity.

## Rollback and upgrade

Use the same pinned install form with a newer reviewed tag when available. For removal or a failed
disposable install, run `scripts/rollback-recallant-install.sh` in dry-run mode first and confirm
only marker-backed Recallant paths shown by the preview.
